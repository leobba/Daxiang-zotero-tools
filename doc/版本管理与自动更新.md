# 版本管理与自动更新

> 本文档说明：怎么提交代码、怎么发版、以及 Zotero 自动更新是怎么串起来的。

---

## 一、版本号的唯一来源

**`package.json` 的 `version` 是唯一事实来源。** 构建时脚手架会把它注入到：

| 注入位置 | 效果 |
|---|---|
| `manifest.json` 的 `version` | Zotero「工具 → 插件」里显示的版本 |
| 设置面板「关于」页的版本号 | 界面上看到的版本 |
| `update.json` 的 `version` | Zotero 靠它判断要不要升级 |

所以**改版本号只改 `package.json` 一处**，不要手改 `manifest.json`（它是构建产物，每次构建都会被覆盖）。

## 二、仓库地址的唯一来源

**`package.json` 的 `repository.url` 是唯一事实来源。** 脚手架从中解析出 `owner` / `repo`，
填进 `zotero-plugin.config.ts` 里的 `{{owner}}` / `{{repo}}` 模板变量，最终生成：

```
manifest.json → applications.zotero.update_url
  = https://github.com/<owner>/<repo>/releases/download/release/update.json

update.json → updates[0].update_link
  = https://github.com/<owner>/<repo>/releases/download/v<version>/<xpiName>.xpi
```

**换仓库只改 `package.json` 那一行。**

## 三、日常开发

```powershell
git add -A
git commit -m "feat: 新增 XXX 功能"
```

提交前建议跑一遍：

```powershell
npm run lint:check     # prettier + eslint
npm test               # 真实 Zotero 中的 35 项行为测试
```

> ⚠️ 跑 `npm test` / `npm start` 之前，用 `scripts/stop-dev-zotero.ps1` 结束**开发/测试实例**。
> 不要用 `Get-Process zotero | Stop-Process` —— 那会把你**自己正在用的 Zotero** 一起杀掉。
> 该脚本按命令行里的 `.testkit` / `.scaffold` 路径区分，只动隔离实例。

## 四、发版

### 方式 A：GitHub Actions（推荐，不需要在本地放 token）

仓库里已经有 `.github/workflows/release.yml`，触发条件是 **推送 `v` 开头的 tag**：

```powershell
# 1. 改版本号（三选一，或直接手改 package.json）
npm run release:patch    # 0.2.0 → 0.2.1   修 bug
npm run release:minor    # 0.2.0 → 0.3.0   加功能
npm run release:major    # 0.2.0 → 1.0.0   不兼容变更

# 2. 推代码与 tag
git push origin main --follow-tags
```

> `npm run release:*` 走的是 `zotero-plugin release <level> -y`：它会**改版本号 + 构建 + 提交 + 打 tag**。
> 如果本地没有 `GITHUB_TOKEN`，它在「创建 GitHub Release」那一步会失败 ——
> 这时改用下面的「方式 B 的纯 tag 流程」，把建 Release 交给 Actions 做。

**纯 tag 流程**（本地完全不碰 token）：

```powershell
# 手改 package.json 的 version，然后：
git add package.json
git commit -m "chore: 发布 0.3.0"
git tag v0.3.0
git push origin main --follow-tags
```

Actions 收到 `v0.3.0` 这个 tag 后会跑 `npm run build` + `npm run release`，
用仓库自带的 `GITHUB_TOKEN`（`permissions: contents: write`）创建 Release，
并把 **xpi 与 update.json** 传上去。

### 方式 B：本地发布（需要在本地放 token）

```powershell
# 1. 生成 token：GitHub → Settings → Developer settings → Personal access tokens
#    scope 勾 repo（经典 token）或 Contents: Read and write（细粒度 token）
# 2. 写进 .env（已在 .gitignore 里，不会提交）
#    GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxx
npm run release:minor
```

`zotero-plugin release` 会读 `process.env.GITHUB_TOKEN`（也认 `GH_TOKEN`），
用 `@octokit` 建 Release。

> **不要把 token 写进任何会被提交的文件。** `.env` 已被忽略；`.env.example` 只放占位。

## 五、自动更新的原理与前提

```
Zotero 启动
   └─ 读 manifest 的 update_url
        └─ 拉取 update.json（Release 里的固定地址）
             ├─ 比对 version：不高于当前版本 → 什么都不做
             └─ 更高 → 按 update_link 下载 xpi → 提示/自动安装
```

**三个硬前提：**

1. **仓库必须公开。** Zotero 拉 `update.json` 时不带任何凭据，私有仓库的 Release 资产它拿不到，
   自动更新会**静默失效**（插件本身照常能用，只是不升级）。
2. **Release 里必须有 `update.json`。** 它由 `zotero-plugin release` 生成并上传；
   只推 tag 不建 Release，Zotero 就会 404。
3. **`update_url` 指向的是 tag 为 `release` 的那个 Release**（不是 `v0.2.0`）。
   这是脚手架的约定：`releases/download/release/update.json` 是一个**固定地址**，
   每次发版都覆盖它，Zotero 才不用改地址。xpi 则在 `v<version>` 那个 Release 里。

## 六、检查自动更新是否正常

```powershell
# 1. update.json 能拿到吗（应当返回 JSON，不是 404）
curl https://github.com/<owner>/<repo>/releases/download/release/update.json

# 2. 里面的 update_link 能下载吗
curl -I https://github.com/<owner>/<repo>/releases/download/v0.3.0/myzoterotools.xpi

# 3. Zotero 里看：工具 → 插件 → MyZoteroTools 的版本号
```

Zotero 默认**不会**每次启动都检查更新（它按自己的节奏），想立刻验证可以在
「工具 → 插件」右上角齿轮里点「Check for Updates」。

## 七、需要先做的一次性准备

| 事项 | 说明 |
|---|---|
| 建 GitHub 仓库 | 名字建议与 `package.json` 的 `repository.url` 一致 |
| **设为 Public** | 私有仓库自动更新不可用 |
| 改 `package.json` 的 `repository.url` | 换成真实地址，这一处决定 `update_url` 与下载链接 |
| 首次推送 | `git remote add origin <url>` + `git push -u origin main` |
| 打个初始 tag | `git tag v0.2.0 && git push origin v0.2.0` 触发第一次 Release |

`repository.url` 必须是脚手架能解析的格式：

```
git+https://github.com/<owner>/<repo>.git     ✅
https://github.com/<owner>/<repo>             ✅
git@github.com:<owner>/<repo>.git             ✅
```

改完 `repository.url` 后，**必须重新构建一次**才能让新的 `update_url` 进入 `manifest.json`：

```powershell
npm run build
# 核对
Get-Content .scaffold/build/addon/manifest.json | Select-String update_url
```
