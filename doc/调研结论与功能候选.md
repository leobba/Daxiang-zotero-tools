# MyZoteroTools — 调研结论与功能候选

> 调研日期：2026-10-04　｜　Zotero 10.0.5（Gecko 140 ESR，BuildID 20260930221031）
> 状态：**已完成调研与分析，等待确认后再开发**

## 一、三处推翻了初判的结论

### 1. 「元数据清洗」不该自己做 → 装 Linter for Zotero

初判：你的库 `language` 字段有 `zh` / `zh-CN` / `en` / `eng` / `English` 五种写法，值得写个清洗功能。

修正：**[Linter for Zotero](https://github.com/northword/zotero-format-metadata)（1060★，2026-09-09，中文社区标注兼容 Zotero 10）已完整覆盖**，且做得更多：

- `language` 字段推断
- 期刊缩写规范化（JabRef + LTWA）
- **学位论文类型补全**（你有 6 篇学位论文）
- **中文姓名拼音化**
- 化学式上下标、DOI / 日期规范化
- 导入时自动查重

→ **本项从候选清单撤回。**

### 2. 已交付的「阅读状态」与成熟插件高度重叠

**[Zotero Reading List](https://github.com/Dominic-DallOsto/zotero-reading-list)（578★，2026-09-16，明确支持 Zotero 7.1–10.0）** 已提供：状态集合（可自定义）、Read Status 列、右键菜单、Alt+1..5 快捷键、打开 PDF 自动改状态、**状态 ⇄ 标签双向同步**。状态存 **Extra**。

我们的实现差异只在存储位置：**我们存标签**（好处是能在标签选择器里直接筛选），它存 Extra。

→ **待决策：保留我们的（先修下面的色位 bug）／改用 Reading List／两者并存。**

### 3. 最强机会在「抽取的下游」，不在抽取本身

生态调研结论（证据见 [生态空白分析.md](生态空白分析.md)）：

> 跨论文结构化变量抽取**至今无成熟方案**。最接近的 Zotero-Exitem 仅 **3★**、单次上限 5 篇、抽取列**固定不可自定义**；Systematic Reviewer 仍是 Research Preview。
> 根因：① **Zotero 十年未实现自定义字段**（论坛从 2016 问到 2026-04）；② 官方只允许注册**只读**的 item tree 列；③ LLM 抽取必须人审 + 增量。

现状链路：

```
论文 → [抽取] → [落库] → [审核] → [增量] → [跨论文对比表]
        ↑ 你已有 skill          ↑↑↑↑↑↑↑↑↑↑↑↑↑ 这一段生态空白 ↑↑↑↑↑↑↑↑
          你已有 3686 条术语表
          我们已做导出数据包（稀缺的上游）
```

→ **这条链路与你「农药制剂 + 机器学习」的课题是同一件事**，最终产物就是一张跨论文对比表。

### 2.4 成因：2026-09-21/22 的换库事故

从 `D:\zotero-tools\reports\` 的两份报告读到：

> 用脚本拷贝 sqlite 切换数据库 → 三个库混在一起：主库 `D:\zotero文献`（110 条）、`D:\ZoteroLib`（91 条，从未同步）、`C:\Users\leobba\Zotero`（5MB 空壳）。后果：标签颜色类型错误（Zotero 6 数字色号 → `TypeError`）、`dataDir` 指向无效路径、其它插件被禁用、20 个幽灵附件目录、295MB 附件进回收站。

修复很彻底（772MB 全量回滚备份、字节级校验 prefs、隔离 6 个危险脚本），**但上述两项重复未清理**。

时间线：重复条目自 09-21 02:50 起、重复分类树建于 **09-22 08:17–08:22** —— 都在修复报告（09-21 21:41）**之后**。

## 三、⚠️ 已交付功能里待修的缺陷（色位冲突）

**Zotero 用数字键 1–9 给选中条目快速打彩色标签，`position` 就是键位。** 证据：

```js
// chrome/content/zotero/collectionViewItemTree.js:1966-1974
let position = COLORED_TAGS_RE.exec(event.code)[1] - 1;
let colorData = Zotero.Tags.getColorByPosition(libraryID, position);
```

你当前的彩色标签：

```
position 0: 双语已译   #00A651（绿）   ← 按「1」就是它
position 1: 待翻译     #FF0000（红）   ← 按「2」
```

而 `src/modules/readingStatus.ts` 的 `applyTagColors()` 会传 `position` 0/1/2，`Zotero.Tags.setColor` 在位置冲突时是 **splice 插入**（`data/tags.js:721`），会把你的两个标签往后挤。

**后果：一旦使用阅读状态功能，「双语已译」的快捷键会从 1 变成 3。**

现状：**你的库尚未被改**（`tagColors` 里只有原有两个），因为测试全跑在副本上。

修法（约 3 行）：改为追加（不传 position）+ 仅在标签尚无颜色时设色。
补充约束：**彩色标签每库上限 9 个**，当前已占 2 个。

## 五、Zotero 官方扩展面：6 个入口，已用 3 个

判定标准：全仓库 grep `@memberof Zotero` / `@namespace Zotero` 仅命中 5 个文件。

| 官方入口 | 已用 | 能支撑什么 |
|---|---|---|
| `ItemTreeManager` | ✅ | 列表自定义列 |
| `MenuManager` | ✅ | 18 个菜单目标 |
| `PreferencePanes` | ✅ | 设置面板 |
| **`ItemPaneManager.registerSection`** | ❌ | 条目信息面板区块（按钮、折叠摘要、侧栏图标） |
| **`ItemPaneManager.registerInfoRow`** | ❌ | **官方唯一接近「自定义可编辑字段」的机制**，生态几乎空白 |
| **`Reader.registerEventListener`** | ❌ | **阅读器 8 个注入点**（3 DOM + 5 菜单） |

被低估的官方能力：

- **`Fulltext.getPages(itemID)`** —— 官方直接取 PDF 全文纯文本（现导出功能走 `.zotero-ft-cache` 缓存文件，可改用它）
- **`Items.getLastRead(libraryID)`** —— Zotero 内置「最近阅读」，`Search` 还有 `lastRead` 条件
- **`Search.setScope(searchObj, includeChildren)`** —— 比改全局 pref 干净的检索嵌套

两条硬约束：

1. **`SearchConditions` 不能注册自定义检索条件** → 「智能收藏集」无法成为原生高级搜索的一部分，只能「物化成真实分类」或 `setScope` 劫持。
2. **技术债预警**：Zotero 10 新增 `Plugins.warnRemovedAPICall` / `getPluginFromError`，正在**主动点名清理 monkey-patch**。现有功能①（包装 `CollectionTreeRow.prototype.getSearchObject`）与功能②（DOM 注入）正属清理目标 → 需加版本检测 + 失败降级。

另：**Zotero 10 的多集合选择**被官方博客称为 `Show Items from Subcollections` 的替代方案 → 功能①**应复用原生 pref 作底层**，不要另起递归查询，否则会与 Zotero 10 多选/高级搜索打架。
